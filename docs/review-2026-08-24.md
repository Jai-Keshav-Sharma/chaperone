## B. Fix in the spec BEFORE the wire contract freezes (Law 8)

### B1. Shadow mode is client-controlled — a fail-open bypass (SEVERITY: HIGH)

flows/08 puts `mode: enforce|shadow` in DecisionRequest. If the gate honors an
agent-supplied `mode: shadow`, any agent can self-exempt from enforcement — violating
Law 1 (no fail-open exists) and AARM R1 (no fail-open bypass). The interceptor's
machine is not a trusted boundary for that choice.

Fix: remove `mode` from DecisionRequest entirely. The gate pins mode per
agent/API-key/server config; interceptors report seam type only. Shadow remains an
explicit operator choice — just made server-side, where trust lives.

### B2. requestState HMAC uses undelimited concatenation (violates Law 4)

flows/06 and review-findings-resolution.md:10 define
`requestState = HMAC(key, escalation_id ‖ expires_at ‖ params_binding_hash ‖ agent_id)`.
`expires_at` and `agent_id` are variable-length with digit/hex character overlap;
`‖` over them makes the parse boundary ambiguous — an issued token could be re-parsed
with a shifted expiry/agent split (e.g., a digit of agent_id migrating into
expires_at). Law 4 says: never string-concatenate preimages; everything through
canonical.rs.

Fix: HMAC over `canonical_json` of the tuple, or AEAD with structured fields. One-line
spec fix now; a frozen-contract migration later.

### B3. Identity must bind to the authenticated API key, not an override

flows/06 allows a `CHAPERONE_AGENT_ID` override. In gateway mode that is a spoofing
vector: any caller picks their identity. `agent_api_keys.agent_id` already exists in
the data model — pin identity to the authenticated key server-side. Env-var override
stays valid only for the hook/shim local seams (single-user machines, documented as
best-effort per aarm-mapping R6).

### B4. `chaperone doctor` should run a live enforcement canary

Cheaper-and-stronger replacement for "verify per pinned host version": doctor installs
a test rule denying a benign canary tool call, invokes it through the real host seam,
and verifies the block actually held. Catches A1/A2-class surface divergence at runtime
on the user's actual host version. Doubles as a demoable differentiator
("the only gate that proves its own enforcement is live").

## C. Benchmark honesty (Law 10 is currently unmeetable)

### C1. flows/10 self-contradiction: byte-identical metrics.json is impossible

CI asserts two runs produce byte-identical `metrics.json`, but the file contains
wall-clock p50/p95/p99 — those cannot be identical across runs. Either the assertion
gets quietly disabled or it never passes.

Fix: split the schema. Deterministic section (verdicts, counts, hashes, replay
results) → byte-identical assertion. Latency section → range/epsilon assertion
(e.g., p95 within ±20% of baseline, absolute bound check against the 50ms target).

### C2. Sample size cannot support the headline targets

≥300 scenarios with benign ≥40% ≈ 120 benign rows. False-block ≤1.5% ≈ 1.8 events —
one mislabeled row moves the metric 0.8pp. Recall ≥98.5% on ~180 violation rows
tolerates ~2 misses. The targets sit at the noise floor of the sample.

Fix: synthetic scenarios are cheap — grow to ≥1,000 rows (benign ≥400), and publish
Wilson confidence intervals alongside point estimates. Same discipline as the
already-committed Cohen's κ.

### C3. Demo fragility

flows/09 demo script cites fixed ledger entry numbers (#42, #43, #47, #48). Any
genesis/init change breaks the launch-day demo live. Query entry seqs at runtime.

## D. Small engineering notes

- **Gateway body hashing vs streaming**: `params_hash` = raw body bytes requires full
  buffering before verdict. State it: buffered by design, explicit max-body-size with
  fail-closed reject (this is also the memory-DoS defense). Do not claim byte-perfect
  streaming for governed calls.
- **derived_counters key collision** (data-model.md:162): `counter_key` = hash of
  (agent_id, tool, window_start, param_path), but declarations also differ by
  `decision`/`same_agent` filters. Include the declaration identity in the key or two
  attributes with different filters collide.
- **Late-approval visibility** (flows/03): the escalation TTL window (15 min) should
  be printed in the deny/timeout message so users know how long the retry path stays
  valid.
